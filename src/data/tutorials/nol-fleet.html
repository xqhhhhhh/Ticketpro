程序原理概括

  • 可以保存多个配置，每个配置启动的时候对应一个chrome浏览器，每个浏览器之间是完全隔离的，配置也是完全隔离的
  • 在配置完全后，程序启动之后会进行如下流程：登录——跳转到演出连接，点击立即购买——如果是抢票的话会跳转到预定页面，程序会在预定页进行等待，直到页面的预定按键可以点击——程序会自动点击然后进入排队——进入日期页选座页，如果有座位就自动锁，然后提醒你付款——如果没有座位就运行9分钟，然后自动进入下一轮循环，直到锁到座；锁到票之后电脑会一直响，然后手机也会通过你设置的渠道提醒你，然后你来手动付款就可以
  • 可以批量启动停止，多个配置列表方便配置管理，复制配置可节省配置时间，如果不想该配置启动则可休眠

通用配置

目标选票数量

捡漏强烈建议选1，因为需要一个区域内出现指定数量的票时才会锁，如果你设置2，区域内只有一张票，是不会锁的。

抢票的时候如果排队位次相对比较靠前可以设置多张，如果排队位次相对比较靠后，可能余票比较少的情况，还是建议多个账号多开浏览器，每个设置一，这样之后如果想要在一个区域内，没有抢到票的号可以指定区域进行捡漏。

按需设置票数、日期、时间。（将网站语言设置成中文）

当前如果是旧版界面，输入多个日期，在一轮切区结束之后，会自动跳到下一个日期的场次进行切区找座位

如果是新版界面的话，会在一轮结束之后换下一个日期场次进行刷座位

如果留空的话，默认是选择第一个可选的日期

区域查询顺序

区域默认顺序为优先序号靠前区域的靠前靠中位置；也可以手动选择，按自己选择的顺序查看是否有空余位置。

itp改版后演出座位界面有新、旧两种版本；需要注意区分，下面分别展示了新旧版的界面；如果你开票前不确定是哪种界面，并且你又不想要默认顺序，那你可以新版和旧版都填写（注意，区域号一定且必须是三位数字）

旧版本界面：

注意不是比赛界面，这种界面不需要勾选旧版比赛界面，比赛界面是下面介绍的，进去直接全部是座位，不需要选区的情况

旧版有三种区域查询顺序，三选一：

  1. 默认顺序：也就是什么都不需要填写，默认按照区域号从小到大，001、002、003......001、002、003......这个顺序自动不断切区，直到遇到空位就锁
  2. 自定义顺序：你可以填写多个区域号，中间用逗号分隔，然后回车添加。插件会按照你填写的顺序，只在你输入的这些区域里循环切区。比如你输入002，001，101回车 那插件的切区顺序就是002、001、010、002、001、010......
  3. 选排模式：如果你对座位要求较高，不仅要限定区域，还要限定排，那就可以用这个模式。比如你设置001区前10排，002区前5排，101区前8排；那插件就会按照001、002、101的顺序进行循环切区，然后进入区域后只会在你限定的排里进行查找，即使后面的排有座位也不会选

旧版优先切入有余票区域

如果右侧不显示座位数的话就不需要勾选，显示的话也是选择性勾选即可

有少数场次的旧版场会在列表栏中显示余票数量；勾选这个选项后，插件会改变切区顺序（只是改变优先级而已），优先切入显示余票大于0的区域。但是需要注意的是，官网的这个余票显示是有延迟且刷新很慢的，很多显示有余票的区域其实点进去根本没余票。

旧版只刷有余票区域

这个勾选上的话和上面的区别就是这个只进入右侧显示大于0的区域，而不会进入其他区域

旧版并行区域扫描

如果设置了同时刷多个区，就可以如下，三个区一起切，这样效率会更高，下方小图和主图里出现座位都会锁。但需要注意的是，如果你的网络环境等不是特别好，用这个方式，在同样的切区间隔下，会更容易出现白屏和403，因为这样操作相当于请求频率会变大。如果容易出现白屏和403，那可以调大切区间隔，或者就不要用这个刷多区功能，或者只设置刷两个区域。

FlClash 默认端口一般是 127.0.0.1:7890。如果所有 Chrome 都使用这个端口，它们通常会

共用 FlClash 当前选中的节点。为了把多个 Melon 任务分开，我们要在同一个 FlClash 中额外

创建多个端口：

Melon 任务 1 → 127.0.0.1:17891 → MELON-TASK-01 → 节点 A
Melon 任务 2 → 127.0.0.1:17892 → MELON-TASK-02 → 节点 B
Melon 任务 3 → 127.0.0.1:17893 → MELON-TASK-03 → 节点 C

下方这个代码需要复制到flclash中，其中const TASK_COUNT = 10 表示要创建多少个端口，这个10可以根据自己需求进行修改；脚本会从17891开始连续创建端口，例如 10 个任务会使用 17891 至 17900

const main = (config) => {
  // 需要几个 Melon Fleet 任务，就把这里改成几。
  const TASK_COUNT = 10;

  // 将生成 17891、17892、17893……，保留 FlClash 默认的 7890 不动。
  const START_PORT = 17891;

  const sourceProxies = Array.isArray(config.proxies) ? config.proxies : [];
  const proxyNames = sourceProxies
    .map((item) => (item && item.name ? String(item.name) : ""))
    .filter((name) => name.length > 0);

  if (proxyNames.length === 0) {
    throw new Error("当前订阅没有可供 Melon 多端口使用的独立节点");
  }

  // Melon Fleet 仅通过本机回环地址调用 Mihomo 控制接口。
  // 已配置控制地址时保留代理客户端自己的设置。
  if (!config["external-controller"]) {
    config["external-controller"] = "127.0.0.1:9090";
  }

  const groupNames = [];
  const listenerNames = [];
  for (let index = 0; index < TASK_COUNT; index += 1) {
    const number = index + 1 < 10 ? `0${index + 1}` : `${index + 1}`;
    groupNames.push(`MELON-TASK-${number}`);
    listenerNames.push(`MELON-IN-${number}`);
  }

  const originalGroups = Array.isArray(config["proxy-groups"])
    ? config["proxy-groups"]
    : [];
  const originalListeners = Array.isArray(config.listeners)
    ? config.listeners
    : [];

  // 防止脚本重复应用时生成同名项目。
  config["proxy-groups"] = originalGroups.filter(
    (group) => !group || !groupNames.includes(group.name),
  );
  config.listeners = originalListeners.filter(
    (listener) => !listener || !listenerNames.includes(listener.name),
  );

  for (let index = 0; index < TASK_COUNT; index += 1) {
    const groupName = groupNames[index];

    // 每个任务拥有一个单独的手动选择组。
    config["proxy-groups"].push({
      name: groupName,
      type: "select",
      proxies: proxyNames,
    });

    // 每个本地端口直接交给对应的选择组处理，不再走默认规则。
    config.listeners.push({
      name: listenerNames[index],
      type: "mixed",
      port: START_PORT + index,
      listen: "127.0.0.1",
      proxy: groupName,
      users: [],
    });
  }

  return config;
};
